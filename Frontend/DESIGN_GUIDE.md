# 와글와글 모바일 디자인 시스템 가이드

> 적용 대상: React Native + Expo + TypeScript + Expo Router  
> 기준 화면: Android, 390 × 844px  
> 최종 업데이트: 2026-07-24

이 문서는 초기 UX/UI 설계 원칙과 현재 프로젝트에 실제 적용된 디자인 토큰을 하나로 정리한 기준 문서다. 신규 화면은 이 문서를 우선 적용하고, 임의의 색상·간격·폰트 크기를 추가하기 전에 기존 토큰과 공용 컴포넌트로 해결할 수 있는지 먼저 확인한다.

---

## 1. 핵심 디자인 원칙

### 1.1 쉽고 명확한 경험

- 한 화면에서는 하나의 핵심 행동을 가장 강하게 보여준다.
- 전문 용어보다 사용자가 바로 이해할 수 있는 짧은 문장을 사용한다.
- 중요한 숫자, 상태, 결제 비용은 행동 전에 명확하게 노출한다.
- 결과보다 먼저 필요한 이유를 설명한다.
- 비활성 상태는 숨기지 않고, 사용할 수 없는 이유를 안내한다.

### 1.2 신뢰할 수 있는 경험

- 크레딧 차감·적립은 실행 전에 금액과 대상을 명시한다.
- AI 블러 처리, 채팅 감지, 게시 대기 상태를 시스템 상태로 분명하게 보여준다.
- 결제된 영상과 미결제 영상의 차이를 시각적으로 명확히 구분한다.
- 사용자의 뷰 각도는 프로필 이미지에 준하는 신뢰 지표로 사용한다.

### 1.3 정보는 줄이지 않고 구조화

- 단순화를 이유로 요구사항의 정보나 기능을 삭제하지 않는다.
- 반복 정보는 여러 카드로 나누기보다 한 카드 안의 행 구조를 우선한다.
- 연관된 정보는 가깝게, 다른 정보 그룹은 충분히 떨어뜨린다.
- 구분선보다 여백을 우선하되, 긴 목록에서는 얇은 구분선을 사용할 수 있다.

### 1.4 지도 중심 UX

- 홈과 장소 상세에서는 지도가 화면의 기본 배경이다.
- 지도 위 검색창·필터·현재 위치 버튼은 16~20px 안전 여백을 적용한다.
- 장소 목록은 3단계 바텀시트로 제공한다.
  - 접힘: 맥락을 유지하는 제목과 토글 노출
  - 중간: 대표 카드 1개 노출, 내부 스크롤 가능
  - 전체: 전체 목록 또는 상세 정보 노출
- 바텀시트가 전체로 열렸을 때 현재 위치 버튼은 숨긴다.
- 지도 위 UI와 핀은 불투명한 글래스 무드를 사용할 수 있지만 정보 대비를 해치지 않는다.

### 1.5 과도한 카드 사용 금지

- 모든 요소를 둥근 카드로 만들지 않는다.
- 하나의 정보 그룹 안에서 반복되는 항목은 행과 구분선으로 해결한다.
- 카드가 필요한 경우:
  - 독립된 행동 단위
  - 결제·경고·완료 등 중요한 상태
  - 지도 위에 떠 있는 정보
  - 다른 배경과 분리해야 하는 핵심 요약

## 3. 레이아웃과 그리드

### 3.1 기준 프레임

- 기준 화면: `390 × 844px`
- 고정 폭이 아닌 유동형 모바일 레이아웃
- Safe Area 필수 적용
- 최소 터치 영역: `44 × 44px`

### 3.2 화면 그리드

| 항목                     |   값 |
| ------------------------ | ---: |
| 기본 좌우 여백           | 20px |
| 작은 화면 좌우 여백      | 16px |
| 큰 모바일 화면 좌우 여백 | 24px |
| 컬럼 수                  |    4 |
| 컬럼 거터                | 12px |

반응형 화면 여백은 `useResponsivePadding()`(`src/hooks/useResponsivePadding.ts`)으로 계산한다. 화면마다 너비 분기를 직접 쓰지 않는다.

```ts
// 360dp 기준 20px에 비례, 레이아웃 파괴를 막기 위해 16~28px로 클램핑
const padding = useResponsivePadding();
```

Safe Area inset까지 함께 필요하면 `useScreenLayout()`을 쓰고, 일반 화면은 두 값을 이미 적용한 `ScreenContainer`로 감싼다.

### 3.3 간격 토큰

간격은 원칙적으로 4의 배수로 사용한다. 임의의 값을 새로 만들지 않는다.

## 5. 타이포그래피

### 5.1 폰트 패밀리

기준 폰트는 **Pretendard**다.

```txt
Font Family: Pretendard
본문: 400
필터·탭·라벨: 500
버튼·리스트 제목·섹션 제목: 600
페이지 제목·핵심 숫자·핵심 상태: 700
일반 UI에서는 800 이상 사용 금지
```

> 현재 코드에는 Pretendard 폰트 파일 로딩과 전역 `fontFamily` 적용이 없다. Android 시스템 폰트로 렌더링될 수 있으므로 배포 전 `expo-font`로 Pretendard 400·500·600·700을 로드하고 공통 Text 컴포넌트 또는 전체 스타일에 연결해야 한다.

### 5.2 현재 코드 타이포 토큰

| 토큰           | 크기 | 줄높이 | 굵기 |  자간 | 용도                |
| -------------- | ---: | -----: | ---: | ----: | ------------------- |
| `type.display` |   36 |     46 |  700 |  -0.8 | 큰 숫자·강한 메시지 |
| `type.h1`      |   30 |     39 |  700 |  -0.6 | 페이지 제목         |
| `type.h2`      |   24 |     32 |  700 |  -0.4 | 큰 섹션 제목        |
| `type.h3`      |   20 |     28 |  600 |  -0.3 | 섹션 제목           |
| `type.title`   |   18 |     26 |  600 |  -0.2 | 리스트·카드 제목    |
| `type.body`    |   16 |     25 |  400 | -0.05 | 기본 본문           |
| `type.small`   |   14 |     22 |  400 |  기본 | 작은 본문           |
| `type.label`   |   14 |     20 |  500 |  기본 | 탭·필터·라벨        |
| `type.caption` |   12 |     18 |  400 |   0.1 | 날짜·주소·보조 정보 |

### 5.3 설계 기준과의 차이

초기 정책은 `Body 16/24/-0.1`, `Body Small 14/21`, `Label Large 16/22/600`이다. 현재 구현은 가독성을 위해 Body와 Small 줄높이가 각각 1px 크다. 프로젝트 전역에서는 현재 `theme.ts` 값을 기준으로 통일한다.

### 5.4 텍스트 규칙

- 제목은 약간 좁은 자간을 사용한다.
- 14px 이하 본문은 자간을 과도하게 줄이지 않는다.
- 주소·시간·메타 정보는 `caption`과 `gray400`을 우선한다.
- 본문은 `dark` 또는 `gray600`, 제목과 핵심 숫자는 `dark`를 사용한다.
- 한 줄 말줄임은 장소명·주소처럼 길이가 가변적인 정보에만 사용한다.
- 버튼 문구는 동사형으로 작성한다: `변경 저장`, `영상핀 등록하기`.

## 6. 모서리와 형태

| 토큰          |    값 | 용도                         |
| ------------- | ----: | ---------------------------- |
| `radius.sm`   |   8px | 작은 아이콘 박스, 상태 라벨  |
| `radius.md`   |  12px | 보조 버튼, 작은 카드         |
| `radius.lg`   |  16px | 입력창, 기본 그룹, 일반 카드 |
| `radius.card` |  20px | 독립 카드                    |
| `radius.hero` |  24px | 히어로 카드, 바텀시트, 모달  |
| `radius.pill` | 999px | 칩, 토글, 원형 라벨          |

원칙:

- 반경은 컴포넌트의 중요도와 크기에 비례한다.
- 같은 그룹의 반복 행마다 별도 카드를 만들지 않는다.
- 목록 컨테이너만 둥글게 하고 내부 항목은 구분선으로 나눈다.
- 원형 UI는 프로필 신뢰도, 영상핀 각도, 상태 점 등 의미가 있는 곳에만 사용한다.

## 7. 그림자와 글래스

### 7.1 기본 카드 그림자

```ts
const shadow = {
  shadowColor: colors.dark,
  shadowOffset: { width: 0, height: 5 },
  shadowOpacity: 0.14,
  shadowRadius: 10,
  elevation: 5,
};
```

### 7.2 지도 글래스 그림자

```ts
const glassShadow = {
  shadowColor: '#282626',
  shadowOffset: { width: 0, height: 6 },
  shadowOpacity: 0.14,
  shadowRadius: 18,
  elevation: 7,
};
```

글래스 사용 규칙:

- 지도 위 바텀시트와 검색 UI에서 적극 사용한다.
- 완전 투명한 유리보다 내용이 읽히는 불투명 글래스를 사용한다.
- 카드 본문에는 글래스를 남용하지 않는다.
- 지도 핀은 시트의 무드와 연결하되 플라스틱 질감을 유지한다.

## 8. 아이콘과 이미지

### 8.1 기능 아이콘

- 크기: 16px, 20px, 24px
- 내비게이션 아이콘: 21~22px
- 단색 라인 또는 단순 솔리드
- 내비게이션, 버튼, 목록, 입력창에 사용
- 터치 영역은 아이콘 크기와 무관하게 최소 44px

### 8.2 3D 이미지

- 권장 크기: 72px 이상
- 사용 위치:
  - 온보딩
  - 빈 상태
  - 완료 상태
  - AI 처리 상태
  - 크레딧 획득
- 사용하지 않는 위치:
  - 일반 기능 버튼
  - 촘촘한 목록 행
  - 채팅 요청 수락 카드처럼 정보 밀도가 높은 작은 카드

스타일:

- 소프트 플라스틱
- 파스텔톤
- 낮은 명암 대비와 약한 반광
- 좌측 상단 확산광
- 흐린 접지 그림자
- 전체 색상 3개 이내
- 정면 또는 좌우 상단 15~25도 시점

## 11. 화면별 상태 표현

### 11.1 게시물 등록

- 혼잡도는 4개 세그먼트로 선택
- 실시간 촬영만 허용
- 장소는 현재 위치 20m 내에서 필수 선택
- 등록 후 AI 블러 처리 화면으로 전환
- 처리 중에는 회전 로딩과 `AI를 이용하여 블러 처리중입니다` 표시
- 처리 중인 게시물은 `게시 대기중`으로 표시하고 상세 이동 금지

### 11.2 영상 열람과 결제

- 미결제 영상은 전체 블러
- 3크레딧 차감 전에 확인 모달 표시
- 결제 후 블러 제거
- 게시물을 열람한 사용자에게만 채팅 요청 노출

### 11.3 채팅

| 상태   | 요청자                      | 게시자                 |
| ------ | --------------------------- | ---------------------- |
| 대기   | 요청 완료 안내, 입력 비활성 | 수락·거절 카드         |
| 채팅중 | 정상 입력·대화              | 정상 입력·대화         |
| 종료   | 종료 안내, 입력 비활성      | 종료 안내, 입력 비활성 |

- 외부 연락처 유도 또는 범죄 의심 패턴은 AI 경고 카드로 표시한다.
- 경고 카드는 대화를 삭제하지 않고 흐름 안에 삽입한다.

### 11.4 크레딧

- 적립: `+`, 라임 계열
- 사용: `−`, 중립 계열
- 필터:
  - 유형: 전체 / 사용 / 적립
  - 기간: 오늘 / 1주일 / 1달

### 11.5 마이페이지

- 뷰 신뢰도는 프로필 이미지에 준하는 핵심 지표다.
- 크레딧과 오늘 영상핀 수를 동일한 수준의 요약 정보로 표시한다.
- 활동 히트맵은 실제 달력 시작 요일에 맞춘다.
- 활동량은 회색 → 연두 → 라임 순으로 표시한다.

## 12. 접근성

- 모든 터치 요소는 최소 44 × 44px
- 아이콘 단독 버튼에는 `accessibilityLabel` 제공
- 선택형 컴포넌트에는 `accessibilityState` 제공
- 비활성 항목에는 `disabled`와 비활성 이유 제공
- 색상만으로 상태를 전달하지 않고 상태 문구를 함께 표시
- 본문과 배경 대비를 유지
- 지도 위 UI는 지도 색상과 무관하게 읽을 수 있는 표면 제공
- 로딩 상태는 화면 텍스트로 현재 처리 내용을 알린다.

## 15. 현재 정리해야 할 기술 부채

1. Pretendard를 `expo-font`로 실제 로드하고 전역 적용
2. 화면별 중복 하단 내비게이션을 `BottomNavigation`으로 통합
3. 여유/와글 토글을 `CrowdToggle`로 통합
4. 영상핀 각도 링을 `ViewAngleRing`으로 통합
5. 직접 사용된 HEX를 의미 기반 컬러 토큰으로 이동
6. 화면마다 다른 헤더 타이포를 `AppHeader`로 통일
7. 그림자 값을 `elevation` 토큰으로 통합
8. 레거시 5단계 혼잡도와 현재 4단계 혼잡도 데이터 규칙 정리
