- **날짜**: 2026-07-15
- **주제**: 1.25 인터넷 대란 및 각종 개인정보 유출 사건에 관한 기술적 분석

## 0. 오늘 한 줄 요약

DNS 중앙집중 구조가 무너지면 인터넷 전체가 멈출 수 있다는 것을 보여준 1.25 인터넷 대란(2003)과, 매개변수 조작·외주 검증 부실이 겹쳐 대규모 유출로 이어진 **2014년 KT 개인정보 유출 사건**을 중심으로, "사용자 입력을 신뢰하지 말라"는 시큐어 코딩 원칙과 이후 제도 변화(징벌적 손해배상제, 망분리 완화 흐름)까지 정리한 자료입니다.

## 1. 인터넷 역사 & DNS의 등장

### 배경 흐름

- Yahoo, Google 등 초기 인터넷 기업
- **ARPANet (1969)** → 인터넷의 시초, 미 국방부(DARPA) 프로젝트에서 출발
- **DNS(Domain Name System)** 등장 — 1983년 개발 (폴 모카페트리스)
  - 사람이 외우기 쉬운 도메인 이름(예: naver.com)과 실제 IP 주소를 연결해 주는 **분산구조 데이터베이스(DB)**
  - 비유: 인터넷의 "전화번호부"

### DNS 조회 구조

```
사용자 → Root DNS → 최상위 도메인(.com 등) → 개별 도메인 서버
```

- AWS Route 53 같은 서비스가 이 라우팅을 담당
- a.com, b.com 등 요청마다 각각의 서버로 연결되는 구조

## 2. 1.25 인터넷 대란 (2003년)

### 개요

| 항목 | 내용 |
|---|---|
| 발생일 | 2003년 1월 25일(토) 오후 2시경 |
| 원인 | **슬래머(Slammer) 웜** 바이러스 |
| 공격 대상 | Microsoft SQL 서버의 보안 취약점 |
| 피해 범위 | 전국 인터넷망 약 2시간 마비 |
| 결과 | 정보통신부 장관 책임 사임 |

### 공격 메커니즘

1. 슬래머 웜에 감염된 좀비 PC들이 대량 데이터 생성
2. KT 혜화전화국(관문국)의 DNS 서버로 트래픽 집중 공격
3. 이 허브가 마비되자 트래픽이 다른 백본망으로 우회
4. 연쇄적으로 다른 지역 DNS 서버까지 줄줄이 마비 (전국 확산)

> 💡 **왜 혜화국이 문제였나?**
> 국가 기간망 트래픽이 한 곳(혜화 관문국)에 **중앙 집중**되어 있었던 구조적 문제였습니다. 이 사건 이후 "분산 처리"의 중요성이 부각되었습니다.

### 왜 막지 못했나?

- 취약점은 이미 알려져 있었고 MS가 패치도 배포한 상태였음
- 그러나 관리자 암호 미설정 / 서비스팩(업데이트) 미설치 서버가 많아 급속 전파
- **기본적인 보안 수칙 미준수**가 근본 원인

## 4. 2014년 KT 개인정보 유출 사건 (핵심 사례)

### 공격 방법

- **파로스(Paros)** 프록시 툴로 쿠키 정보 변조
- 9자리 숫자로 된 **고객서비스 계약번호**를 무작위/순차 대입 공격
- 자동화 스크립트 + 자동화 시스템을 제작해 대량 조회

```
공격자 ID/PWD 로그인 → 쿠키 정보 전송받음
→ 쿠키의 계약번호를 타인 것으로 변조
→ 계약번호 일치 시 타인 정보가 그대로 전송됨
```

### 공격 활동 규모

- 3개월간 KT 홈페이지 **1,266만 회** 접속 (로그 기록만 538GB)
- 특정 IP에서 1일 최대 34만여 건 접속 — **그런데도 감지하지 못함**
- 유출 정보로 휴대폰 개통·판매 영업에 활용
- 타 대리점 3곳에 개인정보(500만 건) 판매 → 콜센터까지 차려 영업

> 📌 **왜 이렇게까지 악용됐나?**
> 유출된 정보에 '약정 만료 시점'이 포함되어 있어, 약정이 끝나가는 고객 명단을 확보한 것과 같은 효과가 있었습니다. 이른바 **"성지"** 마케팅 문자의 배경이 여기에 있습니다.

### 유심 복제 이슈 (언론 미보도)

- 당시엔 유심 정보를 리더기로 복제(라이트)할 수 있었음
- 동일 번호의 두 단말기가 동시에 문자/전화를 받는 것이 가능했던 시대
- 지금은 한 기지국에 같은 번호 단말기 2개가 존재하면 이상 감지 → 무력화되지만, 당시엔 기술적으로 막지 못함
- 이 사실은 유출 사건과 함께 발생했지만 **언론에는 보도되지 않음**

### 검거 과정

- 경찰이 **불법 텔레마케팅 단속** 중 우연히 발견 (업체 압수수색 도중 대량 개인정보 보유 확인)
- 공격자가 **자신의 아이디/패스워드**로 로그인해서 공격 → 로그에 흔적이 남아 쉽게 특정됨
- 구속: 김모(29, 고졸 독학 해커), 정모(38, 2007년 해킹 전력)
- 텔레마케팅 대표 박모(37)는 불구속 입건
- 사건이 외부에 알려진 계기: KT 백엔드 개발자가 직접 확인 후 (분노해서) 공개

### KT는 왜 몰랐나? (탐지 실패 원인 분석)

**1. 인프라가 "너무 좋아서" 역설적으로 못 잡음**
- 공격 트래픽이 CPU 점유율을 끌어올렸지만, KT의 부하관리 시스템 Top10 안에는 들지 못함
- 당시 부하 순위 1위는 '가용번호 조회' 기능이었음

**2. 판매점(협력업체) 트래픽을 신뢰하는 구조**
- 판매업체의 "희망번호 조회" 기능이 **for문으로 비효율적으로 구현**되어 1회 조회 시 1,000~1만 번 반복 조회
- 이것이 오히려 부하 순위 Top3 안에 들어가서, 진짜 공격 트래픽이 상대적으로 묻힘

**3. 근본 원인: 개발 구조**
- KT가 직접 개발하지 않고 **외주 용역**(KTDS → 하청 재하청 구조로 추정)으로 진행
- 발주기관(KT)의 검증 책임이 소홀했음

### 사건의 파장

**내부자 공모 의혹**
- 범인이 번 돈의 규모를 보고 경찰이 "KT 보안 담당자와 내통한 것 아닌가" 의심
- KT 보안 운영 담당자를 참고인 조사 → 결국 무혐의로 종결
- 다만 이 과정에서 담당자들의 정신적 스트레스가 극심 → **보안 직군 기피 현상** 발생

**약한 처벌 → 제도 개선의 계기**
- 방통위 과징금 **2억 원**에 그침 (당시 기준으로도 미미한 수준)
- KT 입장에선 "과징금 + 담당자 인건비 정도면 감당 가능" → 보안 투자 유인이 부족했음
- 이 사건이 **징벌적 손해배상제 도입**의 배경이 됨

## 5. 시큐어 코딩 핵심 원칙

> **🔑 한 줄 요약**
> **"모든 사용자 입력을 신뢰하지 말고 반드시 검증하라"**

- URL 매개변수(파라미터) 숫자만 바꿔도 다른 사람의 정보가 노출될 수 있음
  - 예: 학생 정보 관리 시스템에서 접수번호(`apNo`) 파라미터 조작 → 타인의 입학 지원서 노출 (뉴스 사례)
  - 2014년 KT 사건과 **동일한 원리** (매개변수 조작)
- 필수 검증 항목: **경계 검사(Boundary Check)**, **권한 검사(Authorization Check)**
- 원칙을 지켜도 **논리적 오류**, 특히 **권한 오류**는 피하기 어려워 병적으로 집착할 정도의 검증이 필요함

## 6. 결론 정리

### 결론 #1 — 원칙

> 보안 시스템 운영은 **관련 법과 제도**에 기반해야 합니다(실무자 개인 의견이 아님).
> 보안 시스템이 늘어날수록 **사용자 편의성은 반비례**합니다 (트레이드오프).

### 결론 #2 — 내부의 적까지 고려

- 보안 실무자는 **협력업체라도 무조건 신뢰하지 말고 검증**해야 함
- 정보보안 실무자에게는 철저한 **윤리의식**이 필요함
- 사례: 2014년 **KCB(코리아크레딧뷰로)** 협력업체 직원(내부자)이 카드사 고객정보 약 **1억 400만 건**을 약 1,650만 원에 판매

### 결론 #3 — 외주 용역 시스템 철저히 검증

- 대부분의 공공기관 시스템은 나라장터 공개입찰을 통해 외부 업체가 개발
- 외주 개발 시스템에서 보안사고가 발생하면 **책임은 발주기관**에 있음
- 대응 방안
  1. **시큐어 코딩 + 정적 분석** — 1차적 검증 필수
  2. 중요 시스템은 외부 보안전문가에게 **모의해킹** 의뢰
  3. **웹 방화벽** 등 운영 단계 필수 보안 시스템 적용
- 💡 AI 시대 활용: 정적/동적 분석에 AI를 적극 활용할 수 있음 (크롬 플러그인 등으로 AI 연동 분석)

## 7. 정책·제도 변화 (강의 밖 보충 — 최신 동향)

### 공인인증서 폐지 (참고 사례)

- 1999년 도입 → 2020년 12월 폐지 (**21년** 소요)
- '공인'이라는 독점적 지위만 폐지되었고, '공동인증서'로 명칭이 바뀌어 계속 사용 가능
- 법·제도 개편에 오랜 시간이 걸린다는 점을 보여주는 사례

### 망분리 완화/폐지 흐름 (2026년 현재)

- 국정원 **'국가 사이버보안 기본지침'**(2026년 5월 시행)에서 기존 망분리 조항 삭제
- 정보를 기밀/민감/공개 등급으로 나눠 차등 보안 통제(N2SF)로 전환
- 금융권도 일부 금융사(신한·하나·우리은행 등 10곳)를 대상으로 생성형 AI 활용 목적 망분리 규제 해제
- 배경: 망분리는 보안엔 유리하지만 **생성형 AI·클라우드 활용에는 걸림돌** → 효율성 문제로 완화하는 추세

## 9. 느낀 점 및 배운 점


- "오래된 사건"이 아니라 "반복되는 구조"라는 점이 인상적이었습니다.
- 보안 사고는 기술 문제이기 이전에 구조·책임의 문제라는 점을 다시 확인했습니다. KT 사건에서 정작 문제가 된 것은 화려한 해킹 기술이 아니라, 외주 재하청 구조에서 검증 책임이 희미해진 것과 협력업체 트래픽을 무조건 신뢰한 시스템 설계였습니다.
- 탐지 실패의 원인이 "인프라가 부족해서"가 아니라 "너무 많아서"였다는 역설이 특히 기억에 남습니다. 정상 트래픽(비효율적인 for문 반복 조회)이 오히려 공격 트래픽을 가려버렸다는 점은, 모니터링 설계 시 "이상 트래픽 = 무조건 상위권"이라는 단순한 가정이 틀릴 수 있음을 보여 줍니다.
- "시큐어 코딩 원칙을 안다"와 "실제로 지킨다"는 다른 문제라는 점도 확인했습니다. 슬래머 웜도, KT 사건도 모두 이미 알려진 취약점·원칙(패치 적용, 입력 검증)을 지키지 않아서 커진 사고였습니다.
