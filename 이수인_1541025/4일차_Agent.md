# AI Agent 심층 탐구 — 다중 에이전트, RAG, 그리고 강화학습

* **날짜**: 2026-07-16
* **주제**: AI Agent — 평가 및 발전 방향, Deep Research, Memory & Tool, Reasoning & Planning

## 0. 오늘 한 줄 요약

AI 시스템은 단순한 콘텐츠 생성을 넘어 계획, 실행, 결정을 자율적으로 수행하는 에이전트형 AI(Agentic AI)로 진화하고 있으며, 다중 에이전트 협업과 강화학습을 통해 복잡한 실무적 문제 해결의 한계를 극복해 나가고 있다.

## 1. AI Agent란? 인공지능의 새로운 지평

AI 에이전트는 사용자를 대신해 목표를 추구하고 작업을 수행하는 소프트웨어 시스템이다. 인간의 개입 없이 자율적으로 문제를 해결하는 것이 핵심이다.

**AI의 발전 단계**

* **Perception AI (지각 AI)**: 기계학습 기반, 특정 분야의 데이터 해석 및 분석
* **Generation AI (생성형 AI)**: 텍스트, 이미지 등 새로운 콘텐츠 제작
* **Agentic AI (에이전트형 AI)**: 능동적인 작업 수행 및 자율형 문제해결 시스템
* **Physical AI (물리적 AI)**: 현실 세계에서 물리적 실체를 갖고 작동하는 시스템

**AI 에이전트의 5대 주요 특성**

1. **자율성**: 인간 개입 없이 스스로 계획·실행·결정
2. **인식**: 외부 환경과 데이터를 감지 및 해석
3. **기억**: 과거의 맥락과 상황을 기억하여 더 정교하게 대처
4. **추론(계획)**: 큰 목표를 작은 하위 작업으로 분할하여 합리적 행동 계획 구축
5. **학습(적용) 및 동작(도구)**: 피드백을 통해 성능을 향상하고, 필요시 외부 도구(API 등)를 호출

## 2. 멀티 에이전트 시스템 (Multi-Agent System)

단일 LLM은 환각 현상을 겪거나 복잡한 추론에 한계(자기회귀적 성격)가 있으며, 모델 크기를 키워도 성능 향상이 둔화되는 '스케일링 법칙'의 한계에 직면한다. 이를 극복하기 위해 **집단 지성과 수평적 확장, 역할 분담**이 가능한 다중 에이전트 시스템이 필요하다.

**협업의 유형과 메커니즘**

| 유형 | 특징 | 장점 및 단점 |
| --- | --- | --- |
| **역할 분담** | 난이도 판단 → 전문가 모집 → 토론 → 최종 판단 | ❌ 한 에이전트의 오류가 전체의 오류로 이어질 수 있음 |
| **경쟁** | 개별 목표를 우선시하여 서로의 한계를 시험 | ❌ 단일의 강력한 모델에게 효율성이 뒤처질 수 있음 |
| **협력 + 경쟁** | 특정 작업은 협력, 다른 작업은 경쟁 (균형) | ✅ 게이트 시스템이 최적의 전문가를 선택하여 신뢰성 향상 |

**소통 및 조직 구조 (커뮤니케이션 구조)**

* **중앙집중형 (참여자-서비스 제공자)**: 판사(중앙) 에이전트가 다른 LLM들을 호출하여 순위를 책정하고 최상위 결과를 결합한다.
* **탈중앙화 구조**: 에이전트들이 직접 소통하며, 일부가 실패해도 전체 시스템은 작동하므로 확장성이 높다.

## 3. Memory & Tool: 에이전트형 RAG와 도구 학습

LLM의 내장 파라미터는 최신 정보를 알 수 없고 사적 정보에 접근할 수 없다는 한계가 있다. 이를 해결하기 위해 외부 소스를 검색하는 RAG(검색 증강 생성)가 등장했지만, 기존의 선형 RAG는 일회성 검색에 그쳐 여러 단계의 추론이나 교차 검증이 불가능했다.

**에이전트형 RAG (Agentic RAG)**
단순 정보 검색을 넘어 에이전트가 **검색 여부 결정, 도구 선택, 쿼리 생성, 결과 평가 및 재검색** 등의 단계를 직접 조율한다. 이를 통해 맥락을 유지하며 복잡한 조사 작업을 수행할 수 있다.

**도구(Tool) 사용 능력을 위한 모델 학습법**

* **Toolformer**: 언어모델이 스스로 언제, 어떻게 외부 도구를 사용할지 API 호출 예시를 통해 자기 지도 학습(Self-supervised Learning)한다.
* **Gorilla**: 대규모 API 문서 데이터셋(APIBench)으로 미세조정하여 환각 없는 정확한 API 호출을 유도한다.
* **ReTool**: 결과 기반 보상을 주는 PPO(강화학습)를 통해 도구 호출 타이밍과 선택 전략을 학습한다.
* **Search-R1**: 다단계 웹 검색을 수행하며 GRPO(그룹 상대 정책 최적화)를 통해 더 나은 검색 결과에 보상을 부여한다.

**에이전트 연결 프로토콜**

* **MCP (Model Context Protocol)**: 에이전트(클라이언트)를 외부 도구·데이터(서버)와 표준화된 형식으로 연결 (Tools, Resources, Prompts 제공).
* **A2A (Agent2Agent) Protocol**: 에이전트 간 메모리를 공유하지 않고 지시사항과 쿼리만 교환하며 협업할 수 있도록 돕는 통신 규격 (라우터가 쿼리를 적절한 에이전트로 전달).

## 4. 추론(Reasoning)과 계획 수립(Planning)

복잡한 작업을 위해서는 단순 응답이 아닌 단계별 사고 과정이 필수적이다.

**계획 수립 방법론**

* **ReAct**: '생각(Thought)'과 '행동(Action)'을 결합해 도구 사용과 추론을 번갈아 수행.
* **HuggingGPT**: 계획 수립용 LLM이 작업을 세분화하여 각 전문 모델에 분배.
* **Plan-and-Act**: 거시적 계획을 세우는 에이전트와 이를 실행하는 에이전트를 분리.

**추론 시간 연산량 최적화 (Test-Time Scaling, TTS)**
추론 시 컴퓨팅 자원을 더 많이 투입할수록 성능이 향상된다는 법칙이다. 다만 과도한 사고로 인한 연산 낭비를 막기 위해 세 가지 접근이 활용된다.

1. **모델 기반 (가변 길이)**: `<short>`, `<think>` 같은 제어 토큰으로 추론 길이를 조절 (DeGRPO).
2. **추론 결과 기반 (동적 추론)**: 일부 추론을 생성한 후 지금까지의 생각을 요약하며 나아감 (Infty Think).
3. **라우팅 기반**: 쉬운 질문은 연산량을 적게, 복잡한 질문은 많게 동적으로 할당.

## 5. 도메인 특화 에이전트와 강화학습 (Deep Research)

기존의 고정된 '검색 → 추론' 순서는 오류가 축적되는 문제가 있다. 능동적인 정보 탐색(Deep Research) 에이전트는 **동적 피드백 루프**를 형성해 검색 결과에 대해 추론하고, 그 결과를 바탕으로 다음 검색 과정을 조정한다.

**역동적 환경에서의 해결책**

* **분산 처리 및 캐싱**: 다량의 동시 요청 처리 및 웹 크롤링/API 제약 극복.
* **강화학습 훈련 (GRPO 도입)**: 프롬프트 의존성을 벗어나 시행착오를 통해 최적의 전략을 스스로 학습. 올바른 형식(F1 점수)과 사실의 정확도, 논리적 일관성에 복합적인 보상을 부여한다.

**강화학습이 이끌어낸 '창발적 행동(Emergent Behaviors)'**

* **계획 능력**: 다단계 계획을 스스로 수립.
* **교차 검증**: 첫 검색 결과에만 의존하지 않고 추가 정보 확인.
* **성찰적 재검색**: 검색 결과가 부족하면 스스로 쿼리를 수정해 다시 검색.
* **솔직한 회피**: 정보가 불확실할 경우 아는 척(환각)하지 않고 모른다고 대답.

## 6. 평가 및 향후 발전 방향

**현재의 한계점**

1. **높은 비용**: 추론과 다단계 검색이 자원을 많이 소모하므로 고부가가치 작업에 집중해야 함.
2. **순차적 작업의 한계**: 코딩 등 엄격한 순서가 필요한 작업에서는 범용성이 떨어질 수 있음.
3. **상태 관리와 오류 전파**: 중간에 실패했을 때를 대비한 체크포인트 설정 및 복구 메커니즘 필요.
4. **평가의 어려움**: 매 실행마다 결과가 달라 LLM 평가와 인간의 평가를 병행해야 함.

**향후 방향**

* **인간 중심 상호작용**: 완전 자율 시스템보다는 인간의 '조력자'로서의 포지셔닝 및 사고 과정 투명화.
* **하이브리드 시스템**: 범용 에이전트와 도메인 특화 에이전트의 결합.
* **효율적인 TTS 구현**: 중요한 내용만 깊이 추론하고, 비생산적인 검색은 조기에 중단하는 등 연산 최적화.

## 7. 핵심 키워드 정리

| 키워드 | 한 줄 설명 |
| --- | --- |
| **Agentic AI** | 단순 텍스트 생성을 넘어 스스로 계획하고 도구를 사용해 목표를 달성하는 AI |
| **에이전트형 RAG** | 검색-추론-재검색을 반복하며 맥락을 유지하고 복합적인 조사를 수행하는 RAG |
| **ReAct** | '생각'과 '행동(도구 사용)'을 교차 생성하며 복잡한 문제를 해결하는 프롬프팅 기법 |
| **TTS (Test-Time Scaling)** | 사전 학습이 아닌 '추론 단계(Test-Time)'에서 연산량을 늘려 성능을 향상시키는 방법 |
| **GRPO** | 그룹 내 여러 실행 결과를 비교하여 더 나은 결과에 보상을 주는 강화학습 기법 |
| **MCP / A2A** | 에이전트와 외부 도구를 연결(MCP)하거나, 에이전트 간의 소통을 돕는(A2A) 프로토콜 |

## 8. 인사이트 및 느낀 점

이번 학습을 통해 AI 시스템이 단순한 '챗봇'을 넘어 스스로 사고하고 행동하는 '에이전트'로 진화하는 과정을 명확히 이해할 수 있었다. 특히 인상 깊었던 점은 아래 두 가지다.

1. **환각과 성능 한계를 극복하는 아키텍처의 중요성**: 단일 LLM의 한계를 데이터나 파라미터 크기로만 해결하는 것이 아니라, 멀티 에이전트 협업 체계, 에이전트형 RAG, 그리고 Test-Time Scaling을 통해 '구조적'으로 해결하고 있다는 점이 흥미로웠다.
2. **프롬프팅에서 강화학습으로의 패러다임 전환**: 도구 사용과 검색 전략을 프롬프트(규칙)로 강제하는 것에는 유연성의 한계가 있으며, 궁극적으로 PPO나 GRPO 같은 강화학습을 통해 모델이 스스로 최적의 행동 정책을 깨닫게(창발적 행동) 만드는 방향으로 연구가 집중되고 있음을 확인할 수 있었다.

앞으로는 이러한 에이전트들이 통제 불능 상태에 빠지지 않도록 상태(State)를 관리하고 적절한 체크포인트를 두는 **에이전트 엔지니어링** 역량이 무엇보다 중요해질 것으로 보인다.
