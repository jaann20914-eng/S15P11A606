# 0713 학습일지 - ViewReal 카메라 프로토타입

## 오늘 한 일

오늘은 React로 모바일 웹에서 기기의 카메라를 사용할 수 있는 **ViewReal 카메라 프로토타입**을 살펴보고 정리했다. 단순히 카메라 화면을 띄우는 데서 끝나는 것이 아니라, 카메라 권한 요청부터 전·후면 카메라 전환, 사진 촬영과 저장, 사용 환경 확인까지 카메라 기능에 필요한 흐름을 한 번에 구현한 프로젝트였다.

프로젝트 화면은 모바일 사용을 기준으로 최대 너비를 480px로 잡았고, 어두운 배경에 초록색을 포인트 컬러로 사용했다. 카메라가 켜졌는지, 현재 어떤 카메라를 사용 중인지, 실제 해상도는 얼마인지 바로 확인할 수 있게 구성되어 있어 테스트용 프로토타입의 목적이 잘 드러났다.

## 구현 내용을 보며 배운 점

### 1. 브라우저에서 카메라 연결하기

`navigator.mediaDevices.getUserMedia()`를 사용하면 브라우저에서도 기기의 카메라 스트림을 받아올 수 있다. 이 프로젝트에서는 영상만 요청하고 오디오는 제외했으며, 가능하면 1920×1080 해상도로 연결하도록 설정했다.

가져온 스트림은 `<video>` 요소의 `srcObject`에 연결한다. 영상 메타데이터가 준비된 뒤에는 `videoWidth`와 `videoHeight`를 읽어 실제로 적용된 해상도를 화면에 표시한다. 요청한 해상도와 기기에서 제공되는 실제 해상도가 다를 수 있다는 점도 알게 되었다.

### 2. React의 `useRef`로 미디어 객체 관리하기

카메라 기능에서는 `<video>`, `<canvas>`, `MediaStream`처럼 렌더링과 별개로 직접 접근해야 하는 객체가 많다. 이 프로젝트는 각각을 `useRef`로 관리하고 있었다.

- `videoRef`: 실시간 카메라 영상을 표시하는 요소
- `canvasRef`: 현재 영상 프레임을 이미지로 변환하는 요소
- `streamRef`: 카메라 스트림과 트랙을 종료하기 위한 참조

화면에 보여 줄 상태는 `useState`로, DOM이나 스트림처럼 직접 제어할 대상은 `useRef`로 구분하는 방식이 인상적이었다.

### 3. 전면·후면 카메라 전환하기

`facingMode`를 `environment`와 `user` 사이에서 바꾸면 후면 카메라와 전면 카메라를 전환할 수 있다. 전환할 때는 기존 스트림을 먼저 종료한 다음 새로운 모드로 카메라를 다시 시작한다.

이 과정을 보며 카메라를 단순히 다시 요청하기만 하면 안 되고, 기존 트랙을 확실히 정리해야 카메라가 중복으로 점유되는 문제를 줄일 수 있다는 점을 배웠다.

### 4. 현재 화면을 사진으로 저장하기

사진 촬영은 별도의 카메라 API를 사용하는 대신 현재 `<video>` 화면을 `<canvas>`에 그리는 방식으로 구현되어 있다. 이후 `canvas.toDataURL('image/jpeg', 0.9)`로 JPEG 데이터를 만들고, 미리보기 이미지를 누르면 파일로 내려받을 수 있다.

실시간 영상의 한 프레임을 캔버스로 옮기면 이미지로 가공하거나 저장할 수 있다는 흐름을 실제 코드로 확인할 수 있었다.

### 5. 권한과 실행 환경 처리하기

카메라는 사용자가 권한을 거부하거나, 사용할 카메라가 없거나, 다른 앱이 이미 카메라를 사용 중일 때 연결에 실패할 수 있다. 이 프로젝트는 오류 이름에 따라 안내 문구를 다르게 보여 준다.

- `NotAllowedError`: 카메라 권한이 거부된 경우
- `NotFoundError`: 사용할 카메라를 찾지 못한 경우
- `NotReadableError`: 다른 앱에서 카메라를 사용 중인 경우

또한 `getUserMedia` 지원 여부, HTTPS 환경 여부, 모바일 기기 여부를 확인해 정보 카드에 표시한다. 특히 모바일 기기에서 카메라를 사용하려면 일반적으로 HTTPS 보안 환경이 필요하다는 점이 중요했다. 개발 중인 `localhost`는 예외로 허용된다.

### 6. 컴포넌트 종료 시 자원 정리하기

카메라를 끌 때는 `MediaStream`의 모든 트랙에 `stop()`을 호출하고 `<video>`의 `srcObject`도 비운다. `useEffect`의 정리 함수에서도 같은 종료 함수를 호출해 컴포넌트가 사라질 때 카메라가 계속 동작하지 않도록 했다.

카메라나 마이크처럼 기기 자원을 사용하는 기능은 시작 로직만큼 종료 로직도 중요하다는 것을 배웠다.

## 프로젝트 구조

```text
camera-prototype/
├─ public/
│  └─ index.html
├─ src/
│  ├─ App.js       # 카메라 연결, 전환, 촬영 등 핵심 기능
│  ├─ App.css      # 모바일 중심 화면 스타일
│  ├─ index.js     # React 진입점
│  └─ index.css    # 전역 스타일
├─ firebase.json   # Firebase Hosting 설정
└─ package.json    # 의존성과 실행 명령
```

## 사용한 기술

- React 18
- React Hooks (`useState`, `useRef`, `useEffect`, `useCallback`)
- MediaDevices / `getUserMedia`
- Canvas API
- Firebase Hosting

## 실행 방법

```bash
npm install
npm start
```

개발 서버를 실행한 뒤 `http://localhost:3000`에서 확인할 수 있다. 같은 네트워크의 휴대폰에서 테스트하려면 PC의 로컬 IP로 접속해야 하며, 카메라 권한 사용을 위해 HTTPS 설정이 필요할 수 있다.

배포용 파일은 아래 명령으로 생성한다.

```bash
npm run build
```

## 오늘의 정리

이번 프로젝트를 통해 웹에서도 모바일 카메라 기능을 꽤 자연스럽게 구현할 수 있다는 것을 알게 되었다. 특히 카메라 연결 자체보다 **권한 처리, HTTPS 조건, 기존 스트림 정리, 기기별 차이**를 함께 고려해야 안정적인 기능이 된다는 점이 가장 크게 남았다.
